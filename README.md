# Генератор QR-кодов Wi-Fi

Десктопное приложение (Windows / macOS / Linux) на Python + [CustomTkinter](https://github.com/TomSchimansky/CustomTkinter), которое генерирует QR-код для подключения к Wi-Fi сети по SSID, паролю и типу шифрования. QR-код можно отсканировать телефоном для автоматического подключения к сети.

## Возможности

*   **Генерация QR-кодов Wi-Fi:** создаёт QR-код с учётными данными сети и подписью SSID.
*   **Сохранение SSID:** ранее введённые имена сетей сохраняются локально (`~/.wifi_qr_generator/saved_ssids.json`) и доступны в выпадающем списке при следующем запуске. Поле SSID редактируемое — новую сеть можно ввести в любой момент, даже если сохранённых сетей ещё нет.
*   **Автоопределение сетей из ОС:** если сохранённых сетей нет, приложение спрашивает разрешения и, если пользователь согласен, подставляет в список **все** Wi-Fi сети, известные этому компьютеру (не только текущую), а SSID и пароль активной сети — сразу в форму.
*   **Пароли по требованию:** при выборе из списка любой другой известной сети её пароль запрашивается у ОС в этот момент (а не выгружается заранее пачкой), поэтому в `saved_ssids.json` пароли никогда не попадают — там хранятся только имена сетей.
*   **Показ/скрытие пароля.**
*   **Сохранение QR-кода** как PNG через системный диалог "Сохранить как".
*   **Печать QR-кода** напрямую из приложения — открывает системное меню печати изображения.
*   **Автообновление:** при запуске (в собранном exe/бинарнике) приложение проверяет последний релиз на GitHub и, если вышла новая версия, предлагает обновиться одной кнопкой — скачивает нужный файл под вашу ОС и перезапускается уже в новой версии.

## Запрос разрешения на чтение Wi-Fi

Приложение никогда не читает данные о сетях втихую. Если список сохранённых сетей пуст, при запуске появляется отдельное окно с объяснением, что именно будет прочитано и зачем — пользователю достаточно нажать «Разрешить» или «Пропустить» (см. `app/ui/permission_dialog.py`). Само определение выполняется только после явного согласия и полностью локально (`app/core/wifi_detect.py`):

*   **Windows** — через нативный WLAN API (`wlanapi.dll` напрямую, ctypes), а не парсингом текста `netsh` (его подписи полей переведены на системный язык и не читаются напрямую). **Важно:** без прав администратора Windows отдаёт пароль в открытом виде только для активной сети — для остальных известных сетей пароль хранится в защищённом (DPAPI) виде и приложение честно сообщает, что он недоступен, а не подставляет мусор. Запуск от имени администратора снимает это ограничение.
*   **macOS** — `networksetup` (список сетей и SSID) и `security` (пароль из Keychain — система дополнительно спросит подтверждение через свой системный диалог, отдельно для каждой сети).
*   **Linux** — `nmcli` (требует NetworkManager; чтение пароля конкретной сети зависит от прав, выданных этому подключению).

Если определить сеть или пароль не удалось (нет прав, нет нужной утилиты, Wi-Fi выключен), поля просто остаются пустыми, а в строке статуса — понятное объяснение, без ошибок.

## Автообновление

Проверка обновлений (`app/core/updater.py`) обращается к публичному GitHub API за последним релизом и сравнивает его версию с версией текущей сборки (`app/version.py`). Если релиз новее и для текущей ОС есть подходящий файл — показывается диалог с кнопками «Обновить» / «Позже» (см. `app/ui/update_dialog.py`), никакого молчаливого автообновления.

Технические детали:

*   Работает только в собранном приложении (`is_frozen()`); при запуске из исходников через `uv run main.py` заменять нечего — обновление просто не предлагается.
*   Заменить свой же запущенный `.exe` "на лету" нельзя (проверено эмпирически — `os.replace()` падает с `PermissionError`, даже когда все остальные хендлы уже закрыты). Поэтому используется классическая схема: новая версия скачивается рядом со старой (`*.update`), после чего запускается отдельный отсоединённый скрипт-помощник, который дожидается полного завершения текущего процесса (по PID), переименовывает файл и запускает обновлённое приложение. На Windows это PowerShell-скрипт (а не `.bat` — на машинах, где `find.exe` в PATH переопределён утилитами Git for Windows, `tasklist | find` перестаёт работать; отдельно всплыл нюанс, что флаг `DETACHED_PROCESS` при запуске такого помощника обрывает процесс мгновенно — нужен `CREATE_NO_WINDOW`). На macOS/Linux — аналогичный `sh`-скрипт. Если файл так и не удалось заменить, помощник всё равно перезапускает старую версию, чтобы приложение не осталось "потерянным".
*   Версия релиза берётся из тега (`vX.Y.Z`) — при выпуске новой версии не забудьте обновить `__version__` в `app/version.py` (и `version` в `pyproject.toml`) до того, как ставить тег, иначе старые версии не увидят обновление.

## Структура проекта

```
main.py                     # точка входа: python main.py
app/
  version.py               # текущая версия приложения (сверяется с тегом релиза)
  core/
    qr_generator.py         # сборка QR-кода с подписью SSID
    wifi_detect.py          # кросс-платформенное определение сетей и паролей
    storage.py               # сохранение SSID в ~/.wifi_qr_generator
    printing.py               # открытие системного меню печати изображения
    updater.py                # проверка GitHub Releases и самообновление
  ui/
    main_window.py           # главное окно (CustomTkinter)
    permission_dialog.py     # окно запроса разрешения на чтение Wi-Fi
    update_dialog.py          # окно предложения обновиться
tests/                      # pytest-тесты для app/core
pyproject.toml              # зависимости проекта (управляются через uv)
uv.lock                     # зафиксированные версии зависимостей
.github/workflows/release.yml  # сборка и публикация релизов
```

## Установка и запуск

### Вариант 1: готовый исполняемый файл (без Python)

На странице [Releases](https://github.com/UniQlow17/wifi_qr_generator/releases) для каждого тега `vX.Y.Z` автоматически публикуются:

*   `wifi_qr_generator-windows.exe`
*   `wifi_qr_generator-macos`
*   `wifi_qr_generator-linux`

Скачайте файл под свою ОС и запустите (на macOS/Linux потребуется `chmod +x wifi_qr_generator-macos` / `-linux`). Откроется окно приложения — ничего дополнительно устанавливать не нужно.

### Вариант 2: запуск из исходного кода

Управление зависимостями и виртуальным окружением — через [uv](https://docs.astral.sh/uv/) ([установка uv](https://docs.astral.sh/uv/getting-started/installation/)).

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/UniQlow17/wifi_qr_generator.git
    cd wifi_qr_generator
    ```

2.  **Установите зависимости** (uv сам создаст `.venv` по `uv.lock`):
    ```bash
    uv sync
    ```

3.  **Запустите приложение:**
    ```bash
    uv run main.py
    ```

## Использование

1.  Выберите сохранённую/известную сеть или введите новый SSID.
2.  Введите пароль (если применимо) и выберите тип шифрования.
3.  Нажмите «Сгенерировать QR-код».
4.  Нажмите «Сохранить как PNG», чтобы сохранить изображение на диск, или «Печать», чтобы сразу отправить его в системное меню печати.

## Тестирование

```bash
uv sync --group dev
uv run pytest tests/
```

## Сборка релиза (для мейнтейнеров)

Перед тегом обновите версию в `app/version.py` и `pyproject.toml` — иначе установленные у пользователей копии не заметят, что вышло обновление (см. «Автообновление» выше). Затем запушьте тег:

```bash
git tag v1.0.0
git push origin v1.0.0
```

Workflow `.github/workflows/release.yml` соберёт исполняемые файлы через PyInstaller на `windows-latest`, `macos-latest` и `ubuntu-latest` и прикрепит их к GitHub Release для этого тега. Локально то же самое можно сделать так:

```bash
uv sync --group build
uv run pyinstaller --onefile --windowed --name wifi_qr_generator --collect-all customtkinter main.py
```

Готовый файл появится в `dist/`.
